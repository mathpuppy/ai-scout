# tracker-merge — 三线合流出周报

把三条采集线已落盘的产物归并成一份给人看的周报，再压缩出一份群发速览。全程只读输入文件，本技能不发起任何网络请求——周报里的事实全部来自产物，判断是唯一的新增内容。

流程：① 定位产物 → ② 归并选题 → ③ 撰写周报 → ④ 落盘与审计 → ⑤ 群发速览。

## ① 定位当期产物

| 线 | 产物 |
|---|---|
| harness 深度线 | `raw/lines/<date>/agent-harness-brief-<date>.md`（给人看的简报，直读） |
| GitHub 潮流线 | `raw/lines/<date>/trending-<date>.md` |
| 论文线 | `raw/lines/<date>/papers-<date>.md` |

- 目录名 = 该期运行日。每条线取**所在日期目录最新**的一份（同一次运行的三线产物在同一目录）；目录日期与文件名日期不一致照常运行，把实际读到的路径写进周报头部。
- 缺某条线：跳过该线，头部「数据缺口」注明缺了谁；三份全缺则停止，提示先跑对应采集线。
- 完成标准：两份产物（或缺口注明）都已读完，全部事实条目在手上。

## ② 归并选题

- 选题 = 一项具体的技术 / 发布 / 事件 / 新项目。多条事实讲的是同一件事就并成一个选题（模型判断）；论文线条目的 `repo:` 字段与潮流线上榜仓库对得上，即同一选题。
- 纳入标准一句话：**技术有价值、够趋势 → 纳入选题**。同一事件被 ≥2 条线同时点名（如 harness 简报点名 + 潮流线上榜、论文 repo 同时进 GitHub 周榜）= 热度高，优先纳入。
- 每个选题记下事实来自哪条线（harness / 潮流 / 论文），简报里标注。
- 完成标准：输入里每个事实都归入某个选题，或明确舍弃（与 Agent 技术无关 / 窗口外 / 纯传闻）。

## ③ 撰写周报

结构骨架（照此填内容，D 处填实际日期）：

```markdown
# Agent 技术周报 · YYYY-MM-DD（运行日）

> 窗口：GitHub 官方周榜 · harness 线 [D−9, D] · 论文线 [D−8, D−2] · 产物：<三个文件名> · 数据缺口：<有则写>

## TL;DR

| 选题 | 一句话 | 结论 |
|---|---|---|
| <每个选题一行> | <一句概括> | 值得导入 / 值得观望 / 仅记录 |

**本期大盘**：<1-2 句，只压缩自各选题简评。>

## <选题名>
### 事实
- **<条目>** — <一句话描述>（*harness / 潮流*）（[版本 · 日期](URL)）

### 简评
<2-3 句：它是什么、为何现在值得看、值不值得跟。>

**结论**：<标签> — <一句话理由>

## 本周热门（潮流线）
<潮流线未并入选题的项目，一行一个：名称 + 本周星增 + 当前 stars + 定位 + URL；新建项目标「新建」。>

## 本周论文（论文线）
<论文线未并入选题的论文，一行一个：标题 + 机构（保留〔模型判读〕标注）+ upvotes + 一句话贡献 + paper URL；带 repo 的附 repo 名；按 upvotes 降序。>

## harness 监控名单提名
<潮流线候选区原样带过 + 一句话建议；采纳与否由人改 harness-digest 的监控表。>
```

标签口径（中立判断，不设团队上下文——系统没有团队项目信息，判断只基于技术本身的成熟度与适用面，不写「对团队」「对我们要不要用」）：

- **值得导入**：成熟度足够、上手成本低，可直接试用/采用。
- **值得观望**：方向重要，成熟度或适用场景未明，保持关注。
- **仅记录**：有信息价值，无近期采用价值。

- 完成标准：TL;DR 表覆盖全部选题；每个选题三件套（事实 / 简评 / 结论）齐全。

## ④ 落盘与审计

- 写入 `reports/YYYY-MM-DD/agent-tech-brief-YYYY-MM-DD.md`（目录名 = 运行日，不存在则创建；文件名日期 = 运行日）；同日第二份起文件名追加 `-2`、`-3`。
- 审计：三元组（版本 / 日期 / URL）原样来自输入产物；输入里没有的事实不写进周报；缺口如实标注；潮流线的 stars / 周星增数字与口径原样带过，不得改称其他口径的增速（日增量不得写成周增速）。

## ⑤ 群发速览

周报落盘后，把同一份内容压缩成可直接粘贴进团队群的消息，写入 `reports/YYYY-MM-DD/agent-tech-flash-YYYY-MM-DD.md`（目录与文件名日期同上，`-2` 规则同上）。

- 定位：**自足的要点概览**——读者不看完整周报也能掌握全部核心要点。它是周报的有损压缩，零新增事实。
- 全部选题都上，按结论标签分三组，详略两档：**值得看 / 试 每条 3 行**（标题行带日期/版本 →「是什么」取自事实节 1-2 句 →「怎么用」取自简评/结论 1 句，落到适用场景与上手方式）；**值得观望 / 仅记录 每条 1 行**（选题 + 周报 TL;DR 那句话，可更口语）。版本 / 日期可内联带入，均不得引入新事实。
- IM 粘贴友好：无表格、正文不内嵌链接，结尾给周报文件指针；开场 = 本期大盘压缩成 1-2 句，窗口日期放标题。
- 行文按「说给同事听」的口径，直白与精炼并重：能用日常词就不用行业黑话——「成为默认模型」而非「基座化」、「边干活边提问」而非「HITL 异步化」、「有了实锤」而非「实证爆发」、「成本更低」而非「经济学」；技术名词只在必要时保留（API、开源、上下文、token、worktree）；短句直说，一句讲一件事，不堆修饰、不打比方。
- **热门项目模块**固定收录：来自潮流线周星增榜的入选项目，取周星增头部 + 潮流线研判点名的方向代表，合计 3-5 个；已并入选题的不重复列；每条一行（项目名 + 本周星增 + 当前 stars + 一句话定位），窗口内新建的标「新建」；模块开头带一句本周风向。
- **论文模块**固定收录（论文线在产物中时）：取 upvotes 头部 + 论文线研判点名的方向代表，合计 3-5 篇；已并入选题的不重复列；每条一行（标题 + 机构〔保留模型判读标注〕+ upvotes + 一句话贡献），行文同「说给同事听」口径。

结构骨架（照此填）：

```markdown
📡 Agent 技术周报速览 · M-DD～M-DD

<本期大盘 1-2 句>

👉 值得看 / 试（N 条）
1. <选题>（<日期 / 版本，有则带>）
   - 是什么：<事实节 1-2 句>
   - 怎么用：<简评 / 结论 1 句，落到适用场景与上手方式>

👀 值得观望（N 条）
- <选题>：<一句话要点>

🔥 GitHub 本周热门（按周星增）
- 本周风向：<潮流线本线研判的一句话>
- <项目> 本周 +<N> 星（⭐<当前>〔新建〕）：<一句话定位>

📄 本周论文（HF 热榜 · 权威机构）
- <标题>（<机构>〔模型判读〕 · upvotes <N>）：<一句话贡献>

📋 仅记录（N 条）
- <选题>：<一句话要点>

细节与出处（版本 / 日期 / 链接）：reports/<date>/agent-tech-brief-<date>.md
```

- 完成标准：周报 TL;DR 里的每个选题在速览中各占一行，无一遗漏；每个导入条目三件行（标题 / 是什么 / 怎么用）齐全。
