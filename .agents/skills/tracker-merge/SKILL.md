# tracker-merge — 三线合流出周报

把三条采集线已落盘的产物归并成一份给人看的周报，再压缩出一份群发速览。全程只读输入文件，本技能不发起任何网络请求——周报里的事实全部来自产物，判断是唯一的新增内容。

流程：① 定位产物 → ② 归并选题 → ③ 撰写周报 → ④ 落盘与审计 → ⑤ 群发速览。

## ① 定位当期产物

| 线 | 产物 |
|---|---|
| L1 融合线 | `raw/lines/breadth-<date>.md` |
| L2 harness 线 | `reports/agent-harness-brief-<date>.md`（给人看的简报，直读） |
| L3 潮流线 | `raw/lines/trending-<date>.md` |

- 每条线取文件名日期**最新**的一份；三条线日期不一致照常运行，把实际读到的文件名写进周报头部。
- 缺某条线：跳过该线，头部「数据缺口」注明缺了谁；三份全缺则停止，提示先跑对应采集线。
- 完成标准：三份产物（或缺口注明）都已读完，全部事实条目在手上。

## ② 归并选题

- 选题 = 一项具体的技术 / 发布 / 事件 / 新项目。两条事实讲的是同一件事就并成一个选题（模型判断）。
- 纳入标准一句话：**技术有价值、够趋势 → 纳入选题**。同一事件被多条线、多个源同时提到 = 热度高，优先纳入。
- 每个选题记下事实来自哪条线，简报里标注。
- 完成标准：输入里每个事实都归入某个选题，或明确舍弃（与 Agent 技术无关 / 窗口外 / 纯传闻）。

## ③ 撰写周报

结构骨架（照此填内容，D 处填实际日期）：

```markdown
# Agent 技术周报 · YYYY-MM-DD（运行日）

> 窗口：L1/L3 [D−6, D] · L2 [D−9, D] · 产物：<三个文件名> · 数据缺口：<有则写>

## TL;DR

| 选题 | 一句话 | 结论 |
|---|---|---|
| <每个选题一行> | <一句概括> | 值得导入 / 值得观望 / 仅记录 |

**本期大盘**：<1-2 句，只压缩自各选题简评。>

## <选题名>
### 事实
- **<条目>** — <一句话描述>（*L1/L2/L3*）（[版本 · 日期](URL)）

### 简评
<2-3 句：它是什么、为何现在值得看、团队要不要跟。>

**结论**：<标签> — <一句话理由>

## 新兴项目
<L3 未并入选题的项目，一行一个：名称 + 定位 + URL。>

## L2 监控名单提名
<L3 候选区原样带过 + 一句话建议；采纳与否由人改 harness-digest 的监控表。>
```

标签口径：

- **值得导入**：对团队当前项目可直接试用/采用。
- **值得观望**：方向重要，成熟度或适配未明，保持关注。
- **仅记录**：有信息价值，与团队导入无关。

- 完成标准：TL;DR 表覆盖全部选题；每个选题三件套（事实 / 简评 / 结论）齐全。

## ④ 落盘与审计

- 写入 `reports/agent-tech-brief-YYYY-MM-DD.md`（运行日）；`reports/` 不存在则创建；同日第二份起文件名追加 `-2`、`-3`。
- 审计：三元组（版本 / 日期 / URL）原样来自输入产物；输入里没有的事实不写进周报；缺口如实标注。

## ⑤ 群发速览

周报落盘后，把同一份内容压缩成可直接粘贴进团队群的消息，写入 `reports/agent-tech-flash-YYYY-MM-DD.md`（同日 `-2` 规则同上）。

- 定位：**自足的要点概览**——读者不看完整周报也能掌握全部核心要点。它是周报的有损压缩，零新增事实。
- 全部选题都上，按结论标签分三组，详略两档：**值得看 / 试 每条 3 行**（标题行带日期/版本 →「是什么」取自事实节 1-2 句 →「对我们」取自简评/结论 1 句，落到团队动作）；**值得观望 / 仅记录 每条 1 行**（选题 + 周报 TL;DR 那句话，可更口语）。版本 / 日期可内联带入，均不得引入新事实。
- IM 粘贴友好：无表格、正文不内嵌链接，结尾给周报文件指针；开场 = 本期大盘压缩成 1-2 句，窗口日期放标题。
- 行文按「说给同事听」的口径，直白与精炼并重：能用日常词就不用行业黑话——「成为默认模型」而非「基座化」、「边干活边提问」而非「HITL 异步化」、「有了实锤」而非「实证爆发」、「成本更低」而非「经济学」；技术名词只在必要时保留（API、开源、上下文、token、worktree）；短句直说，一句讲一件事，不堆修饰、不打比方。
- **新项目模块**固定收录：来自 L3 线产物的入选项目，取 stars 头部 + L3 研判点名的方向代表，合计 3-5 个；已并入选题的不重复列；每条一行（项目名 + 星标数 + 一句话定位），模块开头带一句本周风向。

结构骨架（照此填）：

```markdown
📡 Agent 技术周报速览 · M-DD～M-DD

<本期大盘 1-2 句>

👉 值得看 / 试（N 条）
1. <选题>（<日期 / 版本，有则带>）
   - 是什么：<事实节 1-2 句>
   - 对我们：<简评 / 结论 1 句，落到团队动作>

👀 值得观望（N 条）
- <选题>：<一句话要点>

🆕 GitHub 新项目（本周新建、星标快涨）
- 本周风向：<L3 本线研判的一句话>
- <项目> ⭐<N>：<一句话定位>

📋 仅记录（N 条）
- <选题>：<一句话要点>

细节与出处（版本 / 日期 / 链接）：reports/agent-tech-brief-<date>.md
```

- 完成标准：周报 TL;DR 里的每个选题在速览中各占一行，无一遗漏；每个导入条目三件行（标题 / 是什么 / 对我们）齐全。
