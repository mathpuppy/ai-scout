# tracker-merge — 两线合流出一份周报

把两条采集线已落盘的产物归并成**一份**周报：给人看、可群发、可渲染长图。全程只读输入文件，本技能不发起任何网络请求——周报里的事实全部来自产物，判断是唯一的新增内容。不做跨线归并：两线事实基本不相交，同一项目被两线点名时各按本线口径写条目。

长图渲染不在本技能内：`run-weekly.sh` 末尾调 `scripts/render-brief.mjs` 把周报渲染成 PNG，本技能只需保证产物符合④的结构契约。

流程：① 定位产物 → ② 归并与撰写 → ③ 落盘与审计。

## ① 定位当期产物

| 线 | 产物 |
|---|---|
| harness 深度线 | `raw/lines/<date>/agent-harness-brief-<date>.md`（给人看的简报，直读） |
| GitHub 潮流线 | `raw/lines/<date>/trending-<date>.md` |

- 目录名 = 该期运行日。每条线取**所在日期目录最新**的一份（同一次运行的两线产物在同一目录）；目录日期与文件名日期不一致照常运行，把实际读到的路径写进周报头部。
- 缺某条线：跳过该线，头部「数据缺口」注明缺了谁；两份全缺则停止，提示先跑对应采集线。
- 完成标准：两份产物（或缺口注明）都已读完，全部事实条目在手上。

## ② 归并与撰写

条目化规则（**只做单线、单 harness 内的轻归并**，不做跨线归并）：

- harness 线：同一 harness 的同类更新合一条（如同一版本序列的多个 patch 合成「八连发」式条目）；架构 / 能力级更新单独成条；同一功能在多个候选版本（DeepSeek alpha/rc）只取最新一条展开。每 harness 最多 2-3 条。
- 潮流线：有独立评估价值的项目（方向代表、差异化明显）出条目，合计 ≤4 条；其余入选项目进「本周热门」清单，不硬凑条目。
- **条目预算**：三组合计约 10-12 条。超出时降档：条目降「其他动态」一行（只列版本号 / 项目名，不写简评）。
- 纳入标准一句话：**技术有价值、够趋势 → 进周报**；拿不准的降档。

三组即结论标签（中立口径，不设团队上下文——系统没有团队项目信息，判断只基于技术本身的成熟度与适用面，不写「对团队」「对我们要不要用」）：

- **值得看 / 试**：成熟度足够、上手成本低，可直接试用/采用。
- **值得观望**：方向重要，成熟度或适用场景未明，保持关注。
- **仅记录**：有信息价值，无近期采用价值。

结构骨架（照此填内容，D 处填实际日期；分组标题固定四个、空组写「（无）」，渲染器依赖标题分色，不得改动措辞）：

```markdown
# 📡 Agent 技术周报 · M-DD～M-DD

<本期大盘 1-2 句，只压缩自各条目。>

## 👉 值得看 / 试（N 条）

### <条目名>（<日期 / 版本，有则带>）〔harness / 潮流〕
- 是什么：<事实 1-2 句>
- 怎么用：<1 句，落到适用场景与上手方式>

## 👀 值得观望（N 条）
- **<条目名>**〔harness / 潮流〕：<一句话要点>

## 📋 仅记录（N 条）
- **<条目名>**〔harness / 潮流〕：<一句话要点>

## 🔥 GitHub 本周热门（按周星增）
- 本周风向：<潮流线研判的一句话>
- <项目> 本周 +<N> 星（⭐<当前>〔新建〕）：<一句话定位>

## 其他动态
- <Harness 名>：vX.Y.Z、vX.Y.W（未展开）

## 出处
- <条目名 / 项目名>：<URL>、<URL>
```

- 值得看/试条目三件行（标题行带日期/版本与来源 / 是什么 / 怎么用）；观望、仅记录每条 1 行。版本 / 日期可内联带入，均不得引入新事实。
- **正文不内嵌链接**，全部链接集中在「出处」附录，逐条对应（渲染长图时出处节不画入图内）。
- 行文按「说给同事听」的口径，直白与精炼并重：能用日常词就不用行业黑话——「成为默认模型」而非「基座化」、「边干活边提问」而非「HITL 异步化」、「有了实锤」而非「实证爆发」、「成本更低」而非「经济学」；技术名词只在必要时保留（API、开源、上下文、token、worktree）；短句直说，一句讲一件事，不堆修饰、不打比方。
- 「本周热门」清单：周星增头部 + 潮流线研判点名的方向代表，合计 3-5 个；已出条目的不重复列；每条一行（项目名 + 本周星增 + 当前 stars + 一句话定位），窗口内新建的标「新建」；开头带一句本周风向。
- 「其他动态」：未展开的 harness 版本与潮流线筛除项一行带过（只列事实，不写评估）。
- 完成标准：三组覆盖全部条目；值得看/试每条三件行齐全；「出处」覆盖全部条目与热门项目；「本周热门」清单覆盖潮流线其余入选项目。

## ③ 落盘与审计

- 写入 `reports/YYYY-MM-DD/agent-tech-brief-YYYY-MM-DD.md`（目录名 = 运行日，不存在则创建；文件名日期 = 运行日）；同日第二份起文件名追加 `-2`、`-3`。
- 审计：三元组（版本 / 日期 / URL）原样来自输入产物；「出处」附录的每个 URL 必须能在输入产物中找到；输入里没有的事实不写进周报；缺口如实标注；潮流线的 stars / 周星增数字与口径原样带过，不得改称其他口径的增速（日增量不得写成周增速）。

## ④ 长图渲染契约（本技能不执行渲染，但结构必须满足）

- 分组标题固定四个 emoji 标题（措辞照骨架，渲染器按关键词分色）；「出处」节以 `## 出处` 开头（渲染器自动跳过，不画入图内）。
- 值得看/试条目必须 `### 标题` + 两个 `- 是什么：` / `- 怎么用：` 行；观望/仅记录/热门/其他动态用 `- ` 行。
- 渲染由 `run-weekly.sh` 调 `scripts/render-brief.mjs` 完成（卡片周刊风），失败只告警不阻塞。
